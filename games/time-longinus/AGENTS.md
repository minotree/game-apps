# 타임 롱기누스 게임 프로젝트 지침

## 프로젝트 결정

| 항목 | 현재 결정 |
| --- | --- |
| 프로젝트 / 패키지 scope | 타임 롱기누스 (Time Longinus) / `@time-longinus` |
| 서비스 목표 | 2154년 AI 침공에 맞서 세 세계선을 오가며 영웅을 육성하는 레트로 텍스트 기반 시뮬레이션 게임 |
| 핵심 흐름 | 월간 4주 스케줄 편성 → 결과 확인 → 스탯·스트레스·크레딧 갱신 |
| 개발 순서 | PWA → 토스 미니앱 → Android/iOS 하이브리드 |
| 첫 구현 범위 | PWA에서 3개 세계선 전환, 월간 4주 스케줄, 크로노 추천 3+1 루프, 로컬 상태 보존 |
| Node / pnpm | Node 24.22.0 확인, `>=20.19.0`; pnpm 10.34.7 (`pnpm.cmd` 사용) |
| 백엔드 / 호스팅 | 현재는 브라우저 로컬 저장만 사용. Supabase, Cloudflare, Vercel은 기능·배포 결정 후 책임을 문서화해 연결 |
| 업로드·검토·출시 | 사용자 승인 전에는 토스 콘솔, 앱 스토어, 호스팅, Supabase에 업로드·배포하지 않음 |

## 구조와 경계

- `apps/web`: PWA UI와 브라우저 로컬 저장 어댑터를 소유한다.
- `packages/contracts`: 프레임워크 비종속 DTO와 게임 상태 계약만 둔다.
- `packages/core`: 순수 게임 규칙을 소유하며 React·브라우저 API·플랫폼 SDK를 참조하지 않는다.
- 토스와 모바일은 실제 개발 단계에서 각자 `apps/toss`, `apps/mobile`으로 추가한다. UI·라우팅·SDK 어댑터를 공유 패키지로 옮기지 않는다.
- 앱은 다른 앱의 소스를 직접 import하지 않고, 공개된 패키지 export만 사용한다.

## 실행과 검증

- 설치: `pnpm.cmd install`
- PWA 개발: `pnpm.cmd dev:time-longinus` (`http://localhost:5173`)
- 타입 검사: `pnpm.cmd typecheck`
- 규칙 테스트: `pnpm.cmd test`
- PWA 빌드: `pnpm.cmd build:time-longinus`

PowerShell 실행 정책으로 `pnpm.ps1`이 막히므로 Windows에서는 `pnpm.cmd`를 사용한다.

## 구현 규칙

- 스트레스·크레딧·스탯을 바꾸는 규칙은 `core`에 두고 단위 테스트를 추가한다.
- 현재 PWA는 설치형 PWA·서비스 워커·오프라인 캐시를 아직 구현하지 않았다. 로컬 상태 보존을 오프라인 게임 지원으로 표현하지 않는다.
- 인증, 동기화, 결제, 광고, 지도, Supabase, Cloudflare Worker, 토스 SDK, Capacitor는 실제 기능 요구와 공식 문서·설치 버전 확인 뒤에만 추가한다.
- 비밀값은 Git·클라이언트 번들·로그에 넣지 않는다. 환경 파일이 필요해지면 `.env.example`에는 자리표시자만 둔다.
- 변경 뒤 관련 `typecheck`/`test`/`build`와 `git diff --check`를 수행하고, 기기·토스 검증은 실제 실행 전까지 미검증으로 기록한다.

## 작업 마무리와 Git

- 사용자가 `마무리하자`라고 요청하면 현재 변경과 미완료 작업을 확인하고, 관련 문서 정리, 필요한 자동 검증, `git diff --check`, 결과 보고를 수행한다.
- `마무리하자`는 스테이징·커밋·푸시·태그·배포·토스 콘솔 업로드·운영 DB 변경·데이터 삭제·자격 증명 교체의 승인으로 해석하지 않는다. 이 작업들은 사용자의 별도 명시 승인이 필요하다.
- 마무리 보고에는 변경 및 문서 요약, 실제 검사 결과와 미검증 항목, 남은 작업, 사용자가 수행할 Git 작업을 구분한다. 별도 요청이 없으면 커밋과 푸시는 실행하지 않는다.

## 기획 기준과 미결정 사항

- 기획은 96개월(8년), 3개 세계선, 세계선별 3개 직업 계열과 4단계 전직, 27개 기본 융합 엔딩, 7개 히든 엔딩을 정의한다. 구현 우선순위는 월간 4주 스케줄 → 5대 고유 스탯 → 전직 → 탐험/전투 → 엔딩/환생이다.
- 화면과 기능은 `docs/architecture/screen-flow.md`의 사용자 흐름을 따른다. 새 게임은 타이틀 → 2154년 프롤로그 → 최초 직업 선택 → 메인 스케줄 순서이며, 환생 포인트 배분은 환생 회차에서만 표시한다.
- 육성 감각과 SF 위기 연출의 참조 범위는 `docs/architecture/design-direction.md`를 따른다. 참조 작품의 보호되는 캐릭터·고유 요소·자산을 복제하지 않는다.
- 기획을 구현하거나 검토할 때는 먼저 `docs/planning/*.md`를 읽고, 상세 서사·편집 이력·로컬 스냅샷에 없는 내용은 연결된 Google Docs 원본에서 확인한다. 원본이 바뀌면 관련 Markdown 스냅샷의 동기화 기준일과 내용을 갱신한다.
- 기획 문서 사이에는 일부 엔딩명과 세부 조건 표현의 차이가 있다. 구현 전에 `docs/decisions/`에서 기준 문서와 정규 명칭·조건을 확정하며, 추측으로 통합하지 않는다.
